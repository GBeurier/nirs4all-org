Préserver sans modifier la source

Le paquet publié nirs4all-tools 0.0.7 inspecte les stores historiques et peut en produire une copie de préservation disjointe, exhaustive et vérifiée. La source conserve son chemin, son inode et ses octets. La V1 refuse toute demande de conversion sémantique vers un nouveau workspace tant qu'un contrat de reconstruction complet n'est pas disponible.

python -m venv /opt/nirs4all-tools-0.0.7
/opt/nirs4all-tools-0.0.7/bin/python -m pip install "nirs4all-tools==0.0.7"
/opt/nirs4all-tools-0.0.7/bin/nirs4all-tools legacy inspect /data/ancien --format text
/opt/nirs4all-tools-0.0.7/bin/nirs4all-tools legacy migrate /data/ancien \
  --output /data/ancien-preserve --copy-only --verify
/opt/nirs4all-tools-0.0.7/bin/nirs4all-tools legacy verify /data/ancien-preserve \
  --manifest /data/ancien-preserve/migration-manifest.json

Codes principaux: 0 préservation copy-only réussie; 20 capacité non supportée, dont la conversion sémantique; 30 échec de vérification; 40 refus de politique de sécurité; 70 erreur interne. Le code 10 est réservé à une future transformation best-effort.

Matrice read / write / migrate

Toute écriture réelle cible un dossier de préservation neuf et disjoint. La V1 ne crée pas de nirs4all-workspace-v2 à partir d'un store legacy et ne déclenche jamais de migration automatiquement. Un changement de cette politique devra être annoncé avec un chemin de migration explicite.

Exemple Python général

import nirs4all

result = nirs4all.run(pipeline="pipeline.yaml", dataset="dataset.yaml")
archive = result.export("./run.n4a")
prediction = nirs4all.predict(model=archive, data="new_dataset.yaml")

Le profil portable strict se sélectionne explicitement avec engine="native". Il demande une pipeline sous forme de liste, un splitter, un modèle Methods supporté et un dataset contenant X, y et sample_ids; consultez le guide Python V1 avant de présenter son export comme une archive Core portable.

Rollback Python explicite

rollback = nirs4all.run(
    pipeline="pipeline.yaml",
    dataset="dataset.yaml",
    engine="legacy",
)

FAQ

Studio doit-il embarquer Python?

Pas comme backend. Un CPython embarqué peut héberger une bibliothèque ou un plugin explicitement choisi, via JSON stdio borné. Le serveur, le store et le scheduler restent Rust.

Studio peut-il revenir automatiquement au backend historique?

Non. Les chemins Studio/Web et les profils Python stricts refusent la capacité indisponible. Le rollback legacy est uniquement un choix visible de l'appelant Python direct.

Un ancien workspace est-il migré à l'ouverture?

Non. La détection est en lecture seule. L'opérateur peut lancer une copie de préservation vers une nouvelle destination et en vérifier le rapport; cette copie n'est pas un workspace V1 reconstruit et ne déclenche aucun basculement automatique.

Cette page annonce-t-elle V1?

Oui. Elle accompagne la ligne stable corrigée nirs4all 1.0.1 / Studio 0.11.3. Le Cockpit donne l'état opérationnel courant; la page de reçu conserve la photographie vérifiable de la publication V1 initiale.
